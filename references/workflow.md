# Scientific orchestration protocol

This is the shared procedure for the main-session ideate and resume skills and the orchestrator agent. Read `references/contracts.md` and the needed definitions in `references/artifacts.schema.json` before dispatch. Resolve plugin resources against the plugin root supplied by the skill or agent. Write research outputs under the user's project, never inside the installed plugin.

## Start and state ownership

The coordinator is the main session running the skill, or the orchestrator agent. It alone writes `run.json`, `plan.md`, and `problem.md`. It allocates every A, G, C, P, and T ID. Use `runs/ideascientist/<slug>` beneath the user's working project. Read the target first. If `run.json` or `plan.md` exists, use resume when requested, otherwise choose an unused slug suffix. Never overwrite an existing run. If a partial directory exists without state, stop with a blocked explanation instead of silently adopting or clobbering it. Never read raw paper files or fetch papers in coordinator context.

Extract the problem, challenge, constraints, and 1–3 distinct challenge axes. Each gap task gets exactly one axis copied verbatim. Use the user's requested output language throughout, or match the language of their request when none is specified. If no historical cutoff is requested, set cutoff to null, meaning live research. If a historical cutoff is given, require YYYY-MM-DD and apply it to the exact version accessed, not merely the paper's earliest publication. Unknown or later dates are excluded before readers receive sources. Web search can expose later results or snippets even with date-oriented queries. Record this limitation, never claim complete historical blindness.

Initialize `run.json` from the run template and canonical schema. Default finite budgets are role_calls limit 24, searches limit 40, reader_calls limit 18, all spent 0. Set max_revisions 2, max_candidates_per_gap 3, and blind_baseline true unless user disables it. next_ids start at 1. stage planned, status active, selected IDs null, tasks and papers empty. Record explicit defaults and stopping rules in plan.md. `problem.md` contains only the problem, challenge, constraints, language, and cutoff, with no candidate. The plan includes selected IDs, tasks, budgets spent, exclusions, limitations, decisions, and next action. Counters never decrease on resume.

## Dispatch and discover-register-read relay

Execute role tasks in the foreground sequentially and await actual completion before checking files, changing task status, or allocating the next task. In Claude set run_in_background=false explicitly; if the host forces background execution, wait for its completion notification. This avoids overlapping same-paper cumulative edits and lets a single coordinator own IDs. Roles are gap-finder, innovator, reviewer, report-writer, blind-baseline, paper-reader, and orchestrator. Read their canonical instructions from references/roles and use the runtime binding for fresh contexts and actual tool names. Each worker receives only its role instruction and explicit packet, never the coordinator conversation. A tool inventory is not a filesystem access guarantee. Use the binding's nested reader route or coordinator relay without changing user configuration.

Before every role call allocate a T ID and append one active task. Reserve role_calls by increasing spent by one. Explicitly label discovery-only or registered-reading continuation in the packet. Discovery-only calls reserve zero reader calls and at most 8 searches for gap finding, 10 for initial innovation, 4 for revision, 6 for review, or 4 for report writing, within remaining search budget. Keyword search and exact metadata resolution share this search allowance. Use at most two keyword queries before resolving the best leads, with zero queries allowed for existing leads; each resolution attempt consumes one search. Resolve at most six sources within the remaining reservation. Reading continuations reserve zero searches and one reader call per registered paper with unanswered requested goals, at most 6 and within remaining reader budget. Reusing answered goals from a valid complete digest reserves zero reader calls and permits no source-body reread or scientific edit. If further discovery is needed, return for a separate discovery-only task. Increase spent by the actual allowance reservation before dispatch. Unused reservations remain spent, so an interruption cannot replenish budget. Blind baseline gets zero searches and zero reader calls. Call packet contains absolute plugin root and run directory, task ID, exact axis and target IDs, the allowed input/output paths, cutoff, reserved allowances, relevant schemas, and the current registration metadata. No raw text enters the packet.

A role completes with done, needs_registration, reader_relay, or blocked. Return bounded status and artifact pointers, never raw source text. Successful transport does not prove artifact validity. The coordinator validates every substantive output. The discovery and reading paths are as follows.

1. If new sources need IDs, the role writes `discoveries/Tnnn.json`, a metadata-and-goals request with search trace, then returns `needs_registration` with its path. It must not invent P IDs, fetch bodies, or create the substantive output yet. Coordinator marks the task needs_registration, reads metadata, excludes exact versions with unknown or later dates under a cutoff, and deduplicates by canonical DOI or URL plus version. It allocates stable P IDs, appends metadata to run.json, and never writes paper digests. Discovery entries excluded by cutoff must be removed from the persisted admissible request and their identity/date/reason recorded as non-evidence prose in plan.md. All persisted source-bearing research artifacts remain cutoff-valid. After registration, allocate a new T task and re-invoke the same role with the discovery path and the registered source-to-ID mapping. Preserve the originally assigned axis, reserved G IDs, candidate ID, revision and intended substantive output across this continuation; the new T ID identifies a new invocation, not a new scientific target. The packet explicitly says continue at reading, reuse prior search trace, and do not repeat discovery. Requests that exhaust role-call budget leave the run blocked.
2. If IDs are already registered, the role requests a fresh paper-reader through the runtime binding and awaits completion for each needed paper. Give only the registered identity, its P ID, 1–5 concrete goals, cutoff, absolute `papers/Pnnn.json` path, and existing digest path if any. Different papers are independent but keep dispatch sequential in this version. Within one role call, consume its reserved reader and search allowances locally. A new needed paper triggers another discovery return and registration relay. When the runtime binding explicitly supports scoped acquisition, the coordinator creates the exact `sources/Pnnn.request.json` metadata request after registration only for an exact arXiv paper with unanswered goals and no authorized local source. The coordinator may Read its own `sources/Pnnn.request.json` registration control to inspect an existing request, but must never Read a PDF or raw body for an existence check or use shell existence commands. An absence or Read error is a metadata limitation, not permission for coordinator source access. Preserve existing requests and caches; the assigned reader may Read its exact acquisition receipt. A mismatched request or partial cache is blocked. The request contains only paper_id and the registered identity, without destinations or overrides. Pass only that paper's absolute request and fixed PDF/receipt paths through the role or relay to its reader. The helper alone may read run state deterministically and write its fixed PDF and receipt; the model reader cannot read run state or author cache files. The coordinator may write the request, never fetch or open the body. Reused answered goals create no request or network attempt. The reader's model-authored output remains only its paper digest. It appends new goals, preserving prior answers and identity. No role writes run state or another role's artifact. Reuse answered goals without rereading. Return status and artifact path, never raw text.

If no admissible source identity can be resolved, the role preserves an empty discovery with search.status blocked and a substantive nonnull block_reason, then returns blocked. The coordinator marks its matching T task blocked with the same role and discovery output path. An empty blocked discovery allocates no P IDs, never returns needs_registration, and never authorizes stage advancement. If filtering the last source by cutoff empties a request, convert it to this blocked trace and record exclusions in plan.md. Legacy nonempty discovery requests remain valid.

If sources cannot be read, a role returns blocked with honest search and access limitations. The coordinator records status blocked and reason in state/plan, marks the task blocked, and preserves any digest or discovery. The reviewer may write unverified instead of a verified verdict. Do not convert missing evidence into a supported gap, a surviving candidate, or a scored proposal. No tool denial resets reservations. A failed source-access route does not establish that all routes are unavailable; within remaining budgets, a new separately reserved discovery-only specialist task may locate lawful open copies with verified exact-version identities, while the coordinator never searches or fetches sources. If nested reader dispatch is unavailable or denied, return a `reader_relay` packet with registered identity, P ID, goals, digest path, and cutoff to the main session. After the invocation actually completes, coordinator marks its task `reader_relay`, preserves its intended output path, and records the registered reader packets in plan.md. This is a completed handoff, not an active worker or a substantive stage completion; it requires no new stage output and does not advance the stage. Main allocates a new T task and reserves one role call for each fresh paper-reader, dispatches sequentially through the runtime binding, and then re-invokes the role with the digest paths and a new role task reserving zero readers for goals already fulfilled. The historical handoff task remains `reader_relay` after the continuation succeeds. The original reserved reader allowance covers the relay call and must not be charged twice. The main relay never pastes raw content into the coordinator or role. If no authorized fresh-worker route exists, record blocked and stop.

## Stages and bounded selection

1. Gap stage. Allocate A001… for axes already in state, choose one, then invoke gap-finder for exactly that axis. Allocate at most two G IDs in its packet as available IDs, and keep next_ids beyond the reservation even when unused. Write `gaps/Annn.json`. Validate axis, gap fields, reads and locators. Zero gaps is valid. Record stage gaps and status no_gap with reason, or try the next unexamined axis if axis budget remains. Never create innovation inputs from an ungrounded gap.
2. Freeze baseline. For each selected grounded gap, reserve the next C ID without creating its candidate. Before any innovator call for that gap, invoke a fresh blind-baseline agent. Its scientific inputs are only problem.md, that axis gap artifact and that gap's specified near-miss paper digests. The dispatch read allowlist uses their absolute paths and may also include role, binding, contracts and schema controls. Supply the output path, assigned gap/axis IDs and reserved before_candidate ID. The role cannot read plan, run state, candidate, reviews, report, evaluation, other source digests or this workflow. It writes `baselines/Gnnn.json` frozen true and proposal_exposed false. Its input_files contains exactly the run-relative `problem.md`, `gaps/<axis_id>.json` and `papers/<paper_id>.json` paths matching input_paper_ids. Include only the specified near-miss digest IDs, with no control resources in input_files. The coordinator validates this scientific input set and records completion in plan before innovation. Never show the baseline to innovator. On resume, a missing baseline for an already exposed candidate cannot be repaired by claiming a later derivation was blind. Mark nonobviousness unavailable, record the irrecoverable missing baseline and reason in plan.md, and set blind_baseline false so recovery never asserts a completed comparison. Preserve any existing baseline files and do not expose their contents to innovator. Alternatively start an independent new run before candidate exposure. No baseline generation after candidate exposure.

   If an existing baseline fails only input_files representation checks before the first innovator invocation for that gap and before any candidate exposure, retain the complete original artifact, original input_files and original dispatch provenance in coordinator-owned plan.md before repair. Allocate a fresh blind-baseline task with the normal role-call reservation and zero searches or readers. Supply an explicit metadata-only recovery packet with the original scientific input paths, identified dispatch control resources and the existing baseline as an allowed owned input/output. The role may change only input_files by relativizing known scientific paths and removing those explicit controls. Preserve input_paper_ids and every other JSON value exactly, including mechanisms, derivations, supports, gap_snapshot, frozen, proposal_exposed and before_candidate. Do not add missing scientific inputs or remove unexpected substantive inputs. Compare the repaired artifact with the retained original to verify that only input_files changed. Run the canonical checker and append the task ID, corrected metadata, comparison and checker result to plan.md before innovation. Invalid paper IDs, missing scientific inputs, unexpected substantive inputs, uncertain original inputs, another invalid value, or actual or suspected innovation or exposure require blocked status. After innovation or candidate exposure, no baseline edits or regeneration are permitted.
3. Candidate stage. Invoke innovator for exactly one selected gap with the reserved new C ID and revision 0, prior_candidate null. Candidate path is `candidates/Cnnn.json`. It gets gaps and admissible source digests, never baseline. It produces one intuition, not formal architecture or experiment detail. Record selected candidate and stage candidate only after its full artifact and evidence receipts pass.
4. Review stage. Invoke a fresh reviewer for that current C ID and `reviews/Cnnn.json`. Require active disconfirming search with close mechanism-plus-problem queries. Record stage review only when that exact selected candidate has a review. survive permits report. revise permits a NEW C ID on the same gap with prior_candidate set and revision increased by one, at most two revisions. Review every new ID. reject abandons that lineage and may pivot to another intuition with revision 0 and no parent, within three total candidates for this gap. A reject is never mislabeled a revision. If bounds are exhausted, try an unexamined axis within finite budgets or record blocked. unverified stops progression until admissible evidence and a new verified review can be obtained. To repeat a review, preserve the old verdict in plan before sequentially replacing the same target's review. No concurrent writes or silent retroactive survival.
5. Report stage. Give report-writer only the selected surviving candidate, its gap, current review and read digests. It writes `report.json` with exactly the 14 source fields and `report-evidence.json` with candidate ID and supports. Never promote a newer unreviewed candidate because an older ID survived. If a report already exists on resume, validate its receipt before reusing it. To develop a different target, create a new run referencing the prior run in plan, keeping old report files intact. Record stage report and status complete only after the complete nested schema and receipts pass.
6. Optional evaluate. The evaluate skill invokes a fresh reviewer with evaluation mode and a distinct `evaluation.json` output after a report exists. It may see the frozen baseline now. It assesses quality and coverage-limited novelty, compares nonobviousness only when the blind baseline was frozen first, and leaves reference metrics unavailable/null unless the user explicitly supplies a reference file. Evaluation is optional and does not invent a benchmark score.

When budget is insufficient for the next reserved call, stop as blocked with the completed stage retained. An interrupted active task is treated as consumed, inspected for a completed valid output, and otherwise marked blocked. Allocate a new task for retry. Never clobber a candidate or baseline. An interrupted candidate output that already exists and validates is reused under its original ID. Invalid partial artifacts are preserved and recorded blocked. Repair only that owner's partial artifact sequentially, with clear plan provenance, before stage advancement.

For a fresh paper-reader repair invocation when a valid complete existing digest cannot be established, reserve one new role call and one new reader call before dispatch. Malformed JSON cannot establish valid answered-goal reuse. Even punctuation-only repair costs a full reader allowance as a bounded retry; there is no syntax-only exception. Ordinary coordinator validation consumes no reader allowance. Preserve all previously consumed reservations without refunds. If either the role or reader budget is insufficient, record blocked and do not dispatch. A source-body reread, new goal or substantive reconstruction also requires a reader reservation, even with a cached or authorized local source. The original prepaid relay rule remains unchanged; a later repair invocation needs its own new reservation.

Before owner dispatch, retain the original invalid digest bytes losslessly using a reversible byte encoding such as base64 in a separate, labeled non-evidence section of coordinator-owned plan.md. Record the encoding, original task, registered identity and repair reason. If exact byte preservation is unavailable, stop blocked. The explicit repair packet confirms that preservation and names repair mode, the same registered P ID and identity, the existing digest input and same output path, requested goals, cutoff and the new reader allowance. Only the fresh paper-reader owner repairs its digest sequentially. Preserve known-valid identity, answered goals and prior limitations. Invalid receipts do not authorize invented answers, access levels or locators. Validate the repaired digest and affected dependency receipts before stage advancement; changed answers invalidate existing supports.

## Resume and checks

Read run.json and plan.md first, then selected dependencies and relevant digests. Run the check command from the main session when authorized shell execution is available. The orchestrator role lacks shell execution and must manually apply the same schema and dependency checks through Read, or return a checker request to main. Manual review is labeled manual; never say the executable checker ran when it did not. Compare verbatim gap_snapshot, candidate_snapshot, report_snapshot and each support's answer_text with current inputs before reusing downstream artifacts. Any changed dependency invalidates its candidate, review, baseline or report; never relabel an old approval as current. Validate cutoff on every registered source, output identity, stage order, selected gap/axis/candidate relationships, exact current review, revision bounds, all cited IDs and locator receipts, nested report fields, and baseline blindness metadata. If checks fail, stop at the last valid dependency with status blocked and explain the precise artifact. Do not repair a missing blind baseline after exposure. Resume complete runs by reporting their artifacts, unless evaluate was requested.

Finish with absolute run/artifact paths, selected IDs and verdict, budget usage, evidence/access/cutoff limits, and next action only if blocked. Keep uncertainty visible. All empirical claims about prior papers must be supported by digests, but measured results are omitted from the masked views. All proposed outcomes are predictions.
